---
title: Configuration
description: Every environment variable the engine and the web app read, with defaults and descriptions.
---

traces runs as two processes: the **engine** (Jaeger access, issue store, ingester, oRPC API) and the **web app** (the dashboard UI). each reads its own environment variables, so set them on the process that owns them. all values are read at startup via Effect `Config`; restart the process to apply changes. [self-hosting](/docs/app/self-hosting) covers how the two fit together.

| Process | Variables |
|---------|-----------|
| engine | `PORT`, `HOST`, `JAEGER_URL`, `DATABASE_URL`, `TRACES_DB`, `INGEST_*` |
| web | `ENGINE_URL`, `PORT`, `HOST` |

## Engine variables

### Listening address

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `PORT` | number | `4000` | port the engine listens on |
| `HOST` | string | `0.0.0.0` | interface the engine binds to |

The engine has no authentication. bind it to a private interface or keep it on a private network, and let only the web app reach it.

### Jaeger connection

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `JAEGER_URL` | string | `http://localhost:16686` | base URL for all Jaeger v2 API calls (Jaeger's v3 HTTP API paths) — no trailing slash |

`JAEGER_URL` must point at the Jaeger HTTP query endpoint. only the engine talks to Jaeger, so Jaeger does not need to be reachable from the browser or from the web app.

```bash
JAEGER_URL=http://jaeger.internal.example.com:16686
```

### Storage

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `DATABASE_URL` | string | _(absent)_ | Postgres connection string — presence switches the storage driver to Postgres |
| `TRACES_DB` | string | `./traces.db` | SQLite file path, relative to the engine's working directory — only used when `DATABASE_URL` is absent |

:::info
**storage selection**: if `DATABASE_URL` is absent, the issue store uses SQLite at the path given by `TRACES_DB`. if `DATABASE_URL` is set, it uses Postgres and `TRACES_DB` is ignored. migrations run automatically at engine startup for both drivers. see [self-hosting](/docs/app/self-hosting) for the SQLite vs. Postgres tradeoff.
:::

### Ingester

The ingester runs inside the engine from startup. it polls Jaeger on a fixed interval and copies error spans into the issue store. All timing values are in milliseconds.

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `INGEST_POLL_INTERVAL_MS` | number | `30000` (30 s) | how often the ingester polls Jaeger for new traces |
| `INGEST_TRACE_LIMIT` | number | `200` | max traces fetched per service per poll window (maps to Jaeger `query.num_traces`); hitting this limit triggers adaptive window shrink |
| `INGEST_OVERLAP_MS` | number | `60000` (1 m) | how far before the cursor each poll reaches back, to catch late-arriving spans |
| `INGEST_INITIAL_LOOKBACK_MS` | number | `3600000` (1 h) | how far back the first poll reaches for a service that has no cursor yet |
| `INGEST_EXCLUDE_SERVICES` | string | `jaeger` | comma-separated service names the ingester skips. the default keeps Jaeger's own self-traces out. set to `none` to exclude nothing (an empty value is treated as unset and falls back to the default) |

`INGEST_TRACE_LIMIT` caps how many traces are fetched in a single Jaeger request. when the response hits the limit, the ingester halves the next window to avoid missing spans — see [concepts → ingester polling](/docs/app/concepts#ingester-polling-and-cursors) for details.

## Web app variables

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `ENGINE_URL` | string | `http://localhost:4000` | base URL of the engine, read by the web server at runtime |
| `PORT` | number | `3000` | port the web server listens on |
| `HOST` | string | _(runtime default)_ | interface the production server binds to |

The browser never calls the engine directly. the web server calls the engine for server-rendered pages and forwards the browser's API calls from `/api/rpc/*` to `${ENGINE_URL}/rpc/*`, so `ENGINE_URL` only has to be reachable from the web server, and the engine needs no CORS configuration. if the engine is down, those forwarded calls return `502 Engine unreachable`.

```bash
ENGINE_URL=http://engine.internal:4000
```

When you run the dev server (`pnpm dev` in `apps/web`), it starts the engine for you unless `ENGINE_URL` is set; with `ENGINE_URL` set it uses that engine and starts none.

## Seed script variables

These are plain `process.env` values read by `scripts/seed.ts`. they control test-data generation only and have no effect on the running app.

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `TRACE_COUNT` | number | `50` | number of root traces to emit |
| `ERROR_RATE` | number | `0.15` | fraction of spans that record an error (0–1) |
| `OTLP_ENDPOINT` | string | `http://localhost:4318/v1/traces` | OTLP HTTP receiver URL for the seed exporter |

```bash
TRACE_COUNT=200 ERROR_RATE=0.4 bun run scripts/seed.ts
```
